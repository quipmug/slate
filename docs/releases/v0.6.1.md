# slate 0.6.1

a maintenance release that fixes the update path and a handful of daily-use
regressions from `0.6.0`.

## highlights

### releases install over each other again

every ci build used to generate a fresh debug keystore, so each apk had a
different signature and android refused to install it over the previous one.
`0.6.1` adds `keystore/slate-debug.jks`, a public debug key committed to the
repository, and signs both debug and release builds with it. the workflow now
verifies the built apk against that certificate, so a release with the wrong
signer fails instead of shipping.

this one release is still a one-time reinstall: `0.6.0` and older were signed
with throwaway keys whose private halves no longer exist. from `0.6.1` onward
`adb install -r` updates in place.

### the dock stops covering detail screens

the floating dock is back to showing only on the three tabs. habit details and
the blocked-app picker get the full screen again, without the dock sitting over
their last row.

### tabs no longer stack screens

switching tabs pops to the start destination, keeps a single copy of each tab
and restores the saved state. back now walks the way it should instead of
through a pile of duplicate screens.

### “today” survives midnight

the app wakes once at local midnight and rolls the date over while it stays
open. no more checking yesterday’s squares after leaving slate on the table
overnight. resume still refreshes the day after a long sleep.

### focus leaves the running state on time

settings now tick while a focus timer is active, so the screen drops out of the
running state when the timer expires instead of waiting for a restart or a
settings change.

### reminders are not replaced on open

opening the app now keeps a reminder that is already waiting to fire, instead of
pushing it to the next day. changing the time still reschedules it immediately.

### one version catalog for plugins

the root gradle file now takes every plugin from `gradle/libs.versions.toml`.
the hilt plugin and compiler are both `2.52`, and ksp is `2.0.21-1.0.28`, so the
versions can no longer drift apart.

## install

from `0.6.1` onward:

```bash
adb install -r slate-debug.apk
```

or open the apk on the phone and allow installs from the app you used to
transfer it. on android 13 and newer, a sideloaded copy may need **app info →
allow restricted settings** before the accessibility service can be enabled.

### coming from 0.6.0 or older

those apks cannot be updated in place. uninstall once:

```bash
adb uninstall com.slate.weekly
adb install slate-debug.apk
```

if the habit history matters, keep it first. the app is debuggable, so `run-as`
can read and write its private data:

```bash
# 1. back up the old app data
adb shell am force-stop com.slate.weekly
adb exec-out run-as com.slate.weekly tar -cf - files databases > slate-data.tar

# 2. replace the old install
adb uninstall com.slate.weekly
adb install slate-debug.apk

# 3. restore before opening the new app
adb exec-in run-as com.slate.weekly tar -xf - < slate-data.tar

# 4. open slate; history, settings and the focus list are back
```

if you never used adb, uninstalling is the simple path; the app has no cloud
copy. from `0.6.1` onward updates keep data on their own.

## checksums

the release publishes `slate-debug.apk.sha256` next to the apk. verify it with:

```bash
sha256sum -c slate-debug.apk.sha256
```

the published apk is signed with the committed public debug key. to check the
signer:

```bash
apksigner verify --print-certs slate-debug.apk
```

the certificate SHA-256 is
`5a698a3ec45b557865ae175806d377aff30627952b1318bdf3ec59acc7e5d474`.
